# Budget-versus-actual reporting

The first reporting implementation compares an immutable budget version with classified transaction cash movements. Its basis is `classified_transaction_cash_movements_v1`: the report uses the canonical transaction decimal amount, currency, timestamp, and the explicit transaction classification code (`customer|vendor|tax|other` plus `money_in|money_out`). A budget line code must match that classification exactly.

Variance is displayed as actual minus budget, without a finance-approved favorable/unfavorable interpretation. This is a cash-movement comparison only. It is not recognized revenue, accrual accounting, statutory profit, or a reconciled finance statement. Invoice totals are not substituted for cash movements. Currency conversion is not performed. Transactions without a valid classification, canonical amount, or currency are excluded and shown as unknown. Transactions in another currency are excluded rather than combined. Budget lines with dimensions remain unknown because transactions do not yet carry an approved dimensional attribution contract. Duplicate budget line codes are treated as ambiguous and are not allocated.

Every generated comparison stores an immutable report snapshot with the selected budget version, period, currency, dimensions, source transaction IDs, excluded records, and calculation basis. A later correction to a source transaction creates a new report run; it does not rewrite the historical snapshot. Accounting reconciliation and finance-approved variance semantics remain deferred validation work.
