## Purpose and boundary

This checklist connects approved company-owner policy to observed repository behavior, representative examples, affected code paths, and the work that must be completed before downstream implementation. It distinguishes three things:

1. **Observed behavior:** what current code/schema does.
2. **Approved owner policy:** what the decision register says should be true.
3. **Open implementation or review gate:** what still needs a technical specification, evidence, or qualified review.

Owner decisions are not independent review or statutory Romanian accounting, tax, payroll, privacy, or legal approval. No schema migration, amount conversion, historical backfill, destructive deletion, or broad financial behavior change is authorized by this checklist. The capability matrix is [#305](https://github.com/deputy-proxy/Management-OS/issues/305), the canonical data contract is [#306](https://github.com/deputy-proxy/Management-OS/issues/306), the currency/precision migration plan is [#307](https://github.com/deputy-proxy/Management-OS/issues/307), and schema implementation is [#308](https://github.com/deputy-proxy/Management-OS/issues/308).

## Required implementation contract before downstream schema work

The canonical contract should define, without assuming a migration:

- **Money:** amount unit, precision, currency, nullable/unknown behavior, intermediate precision, final rounding stage, and examples for each supported workflow.
- **Transaction:** type vocabulary, direction, non-negative amount validation, original-event reference, transfer/fee/refund/reversal relationships, and balance/report effects.
- **Invoices and tax:** canonical payable/receivable total, net/subtotal fields, VAT field meaning, discount and credit-note semantics, currency, lifecycle states, and authorized settlement confirmation.
- **Payment allocation:** deterministic ordering, full-balance constraint, mismatch behavior, idempotency identity, authorization, and audit events.
- **Dates and periods:** source date meaning, per-report date selection, Europe/Bucharest cutoff, finalization/reopening, and current-period correction behavior.
- **Product costs:** direct-cost eligibility, overhead allocation, exact 100% validation, rounding residual representation, and safe recalculation/correction semantics.
- **Payroll:** explicit separation of provisional internal activity estimates from statutory payroll; immutable finalized values and approved corrections.
- **Uploads:** supported file formats/templates by purpose and version, required fields, blocking versus permitted warnings, scanning, preview, confirmation, duplicate/conflict detection, audit, retention and recovery.
- **Authorization and audit:** role/action matrix, designated approvers, self-approval where already approved, evidence requirements, export permissions, notification failure policy, and access/retention controls.
